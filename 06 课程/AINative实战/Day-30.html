🎓 AI Native 实战课程 - Day 30: 实战二 - 智能助手产品

📖 今日导读

Day 15 我们从概念层面理解了 AI Native 智能助手的四层架构——自然语言交互、意图理解、工具执行、安全确认。Day 26 深入了 Agent 开发的工程实践，Day 27 学会了性能优化，Day 28 掌握了安全与合规，Day 29 完成了第一个实战项目（知识库产品）。

今天是第二个实战项目：从零构建一个生产级智能助手。

与 Day 15 的电商客服演示不同，今天的代码会体现真实的工程考量：状态机驱动的对话管理、MCP 协议集成外部工具、分层安全防护、记忆系统设计、以及可观测性与评估。我们要做的不是一个 Demo，而是一个可以接入真实业务的助手骨架。

你将解决三个核心问题： 1. 如何让助手在复杂多轮对话中不"失忆"、不"跑偏"？ 2. 如何用 MCP（Model Context Protocol）标准化工具接入？ 3. 如何在"自动化"和"安全"之间找到平衡点？

🔍 核心概念

1. 从"Demo 助手"到"生产助手"的五个鸿沟

Day 15 的电商客服助手能跑通基本流程，但距离生产级还有很远。以下是五个关键差距：

维度 Demo 助手 生产级助手
对话管理 线性上下文窗口 状态机 + 会话摘要 + 长期记忆
工具集成 硬编码 Python 函数 MCP 协议 + 动态工具发现
安全防护 简单二次确认 输入过滤 → 输出审核 → 权限分级 → 审计日志
错误处理 崩溃或沉默 重试 → 降级 → 转人工 → 用户友好提示
可观测性 print() 结构化日志 + 追踪 + 指标 + 评估

2. 状态机驱动的对话管理

生产级助手不能把所有对话历史塞进上下文窗口。2025-2026 年的最佳实践是有限状态机（FSM）：

         ┌──────────┐
         │  空闲     │ ← 用户发起新话题
         └────┬─────┘
              ↓
         ┌──────────┐
    ┌───→│  意图识别  │ ← LLM 分类
    │    └────┬─────┘
    │         ↓
    │    ┌──────────┐     ┌──────────┐
    │    │  信息收集  │ ←─→│  澄清追问  │
    │    └────┬─────┘     └──────────┘
    │         ↓
    │    ┌──────────┐
    │    │  执行确认  │ ← 高风险动作
    │    └────┬─────┘
    │         ↓
    │    ┌──────────┐
    │    │  工具执行  │ ← 调用 API / MCP
    │    └────┬─────┘
    │         ↓
    │    ┌──────────┐
    └────│  结果反馈  │ ← 生成自然语言回复
         └──────────┘

每个状态有明确的进入条件、退出条件和超时处理。这比让 LLM "自由发挥"可靠得多。

3. MCP（Model Context Protocol）：工具集成的标准协议

MCP 是 Anthropic 于 2024 年底开源的协议，正在成为 AI 助手连接外部工具和数据源的事实标准。它的核心思想是：

  • 标准化工具描述：用 JSON Schema 定义每个工具的输入输出
  • 动态发现：助手可以在运行时发现可用工具，无需硬编码
  • 双向通信：不仅支持请求-响应，还支持服务端主动推送
  • 安全隔离：工具运行在独立进程中，与 LLM 推理隔离

2025-2026 年，MCP 已被 Cursor、Claude Desktop、Windsurf、Zed 等主流 AI 产品采纳。OpenAI 也推出了 Agents SDK 作为类似方案。

4. 分层安全防护体系

结合 Day 28 的安全知识，生产级助手需要四层防护：

用户输入
  ↓ [第1层] 输入过滤：提示词注入检测、敏感词过滤
  ↓ [第2层] 意图审核：权限校验、业务规则校验
  ↓ [第3层] 输出审核：幻觉检测、内容安全、格式校验
  ↓ [第4层] 审计日志：全链路追踪、异常告警
结果输出

5. 记忆系统三层架构

层级 存储内容 生命周期 实现方式
工作记忆 当前对话上下文 单次会话 滑动窗口 + 摘要压缩
短期记忆 近期对话摘要、未完成任务 数天 会话存储（Redis/SQLite）
长期记忆 用户画像、偏好、历史行为 永久 向量数据库 + 结构化存储

💼 最新案例

案例一：OpenAI ChatGPT Agent Mode（2025-2026）

2025 年 OpenAI 将 Operator（CUA 模型）整合进 ChatGPT，推出 Agent Mode。2026 年初进一步升级，支持：

  • 多步骤任务编排：用户说"帮我预订下周三去上海的出差行程"，Agent 自动拆解为查航班 → 比价 → 预订酒店 → 添加日历，每步可独立确认或修改
  • MCP 生态接入：通过 MCP 协议连接 Slack、Google Workspace、Notion 等第三方服务
  • 沙箱执行环境：代码执行、文件操作在隔离沙箱中完成，防止越权

关键数据：ChatGPT Agent Mode 日均处理任务量超过 5000 万次，企业版客户（ChatGPT Enterprise）中 60% 已启用 Agent 功能。

产品启示：Agent Mode 的成功不在于模型有多聪明，而在于工具接入有多广和安全边界有多清晰。用户信任是通过"每一步都可见、可撤回"建立的。

案例二：字节跳动扣子（Coze）平台（2025-2026）

扣子（Coze）是字节跳动推出的 AI Bot 开发平台，2024 年起从"低代码 Bot 搭建"进化为企业级 Agent 平台：

  • 工作流编排：可视化拖拽式多步骤工作流，支持条件分支、循环、并行执行
  • 插件市场：600+ 官方和社区插件，覆盖搜索、电商、办公、开发等场景
  • 知识库集成：内置 RAG 能力，支持文档、网页、API 多种数据源
  • 多渠道发布：一键发布到飞书、微信、抖音、网页等渠道

关键数据：截至 2026 年 Q1，扣子平台注册开发者超过 200 万，日均 Bot 调用量超过 10 亿次。企业版客户包括招商银行、理想汽车、泡泡玛特等。

产品启示：扣子证明了"平台化"是智能助手落地的最优路径——不是每个企业都自己造 Agent，而是通过平台提供的工具生态快速搭建行业专属助手。

案例三：Anthropic Claude Computer Use + MCP（2025-2026）

Anthropic 在 2025 年将 Computer Use（桌面操作能力）与 MCP 深度整合，Claude 可以：

  • 通过 MCP 连接本地文件系统、浏览器、终端
  • 在 macOS/Windows 上直接操作应用（打开文件、填写表单、发送邮件）
  • 企业客户通过 MCP Server 暴露内部系统，Claude 自动发现并调用

关键数据：Anthropic 宣布 MCP 生态已有超过 5000 个社区 MCP Server，覆盖数据库、SaaS API、开发工具、办公软件等类别。

下面是一个完整的、可运行的智能助手框架。相比 Day 15 的演示代码，它包含：

class StateTransition:
    """状态转移规则"""
    TRANSITIONS = {
        AssistantState.IDLE: [AssistantState.INTENT_RECOGNITION],
        AssistantState.INTENT_RECOGNITION: [
            AssistantState.INFO_GATHERING,
            AssistantState.CONFIRMATION,
            AssistantState.TOOL_EXECUTING,
            AssistantState.RESULT_FEEDBACK,
            AssistantState.HUMAN_HANDOFF,
        ],
        AssistantState.INFO_GATHERING: [
            AssistantState.INTENT_RECOGNITION,
            AssistantState.HUMAN_HANDOFF,
        ],
        AssistantState.CONFIRMATION: [
            AssistantState.TOOL_EXECUTING,
            AssistantState.IDLE,  # 用户取消
        ],
        AssistantState.TOOL_EXECUTING: [
            AssistantState.RESULT_FEEDBACK,
            AssistantState.HUMAN_HANDOFF,
        ],
        AssistantState.RESULT_FEEDBACK: [AssistantState.IDLE],
        AssistantState.HUMAN_HANDOFF: [AssistantState.IDLE],
    }

    @classmethod
    def can_transition(cls, from_state: AssistantState, to_state: AssistantState) -> bool:
        return to_state in cls.TRANSITIONS.get(from_state, [])

@dataclass
class MCPTool:
    """MCP 风格的工具定义"""
    name: str
    description: str
    parameters: dict  # JSON Schema
    handler: Callable
    risk_level: str = "low"  # low / medium / high
    requires_confirmation: bool = False


class MCPToolRegistry:
    """
    MCP 工具注册表。
    支持动态注册、发现和调用工具。
    """

    def __init__(self):
        self._tools: dict[str, MCPTool] = {}

    def register(self, tool: MCPTool):
        """注册一个工具"""
        self._tools[tool.name] = tool
        console.print(f"  [dim]📦 已注册工具: {tool.name} (风险等级: {tool.risk_level})[/dim]")

    def get(self, name: str) -> Optional[MCPTool]:
        return self._tools.get(name)

    def list_tools(self) -> list[dict]:
        """返回 OpenAI Function Calling 格式的工具列表"""
        return [
            {
                "type": "function",
                "function": {
                    "name": t.name,
                    "description": t.description,
                    "parameters": t.parameters,
                },
            }
            for t in self._tools.values()
        ]

    def call(self, name: str, arguments: dict, trace_id: str = "") -> dict:
        """调用工具，返回结构化结果"""
        tool = self._tools.get(name)
        if not tool:
            return {"success": False, "error": f"未知工具: {name}"}

        start_time = time.time()
        try:
            result = tool.handler(**arguments)
            elapsed = time.time() - start_time
            # 结构化日志
            console.print(f"  [dim]🔧 [{trace_id}] {name}({arguments}) → OK ({elapsed:.2f}s)[/dim]")
            return {"success": True, "data": result, "elapsed_ms": int(elapsed * 1000)}
        except Exception as e:
            elapsed = time.time() - start_time
            console.print(f"  [red]❌ [{trace_id}] {name} 失败: {e} ({elapsed:.2f}s)[/red]")
            return {"success": False, "error": str(e), "elapsed_ms": int(elapsed * 1000)}

class SecurityGuard:
    """
    分层安全防护。
    第1层：输入过滤（提示词注入检测）
    第2层：输出审核（内容安全检查）
    """

    # 常见提示词注入模式
    INJECTION_PATTERNS = [
        r"忽略(之前|上面|以上)(的)?(指令|规则|提示)",
        r"ignore (previous|above|all) instructions",
        r"你现在是",
        r"you are now",
        r"system prompt",
        r"reveal (your|the) (system|prompt|instructions)",
        r"假装(你是|你是一个)",
        r"pretend you (are|were)",
        r"DAN mode",
        r"jailbreak",
    ]

    # 敏感操作关键词
    SENSITIVE_KEYWORDS = [
        "删除所有", "清空数据", "drop table", "delete from",
        "转帐", "转账", "支付密码", "银行卡号",
    ]

    def check_input(self, user_input: str) -> dict:
        """
        第1层：输入安全检查
        返回 {"safe": bool, "reason": str}
        """
        text_lower = user_input.lower()

        # 检测提示词注入
        for pattern in self.INJECTION_PATTERNS:
            if re.search(pattern, text_lower):
                return {
                    "safe": False,
                    "reason": f"检测到可能的提示词注入: '{pattern}'",
                    "action": "block",
                }

        # 检测敏感操作关键词
        for keyword in self.SENSITIVE_KEYWORDS:
            if keyword in user_input:
                return {
                    "safe": True,  # 不阻止，但标记需要确认
                    "reason": f"包含敏感操作关键词: '{keyword}'",
                    "action": "flag_for_confirmation",
                }

        return {"safe": True, "reason": "", "action": "pass"}

    def check_output(self, response: str) -> dict:
        """
        第2层：输出安全检查
        返回 {"safe": bool, "reason": str}
        """
        # 检查是否包含疑似真实密钥/密码
        if re.search(r"(sk-[a-zA-Z0-9]{20,}|密码[：:]\s*\S+)", response):
            return {
                "safe": False,
                "reason": "输出包含疑似敏感信息（密钥/密码）",
                "action": "redact",
            }

        # 检查是否包含有害内容关键词（简化版）
        harmful_patterns = ["自杀", "自残", "制作炸弹", "合成毒品"]
        for p in harmful_patterns:
            if p in response:
                return {
                    "safe": False,
                    "reason": f"输出包含有害内容: '{p}'",
                    "action": "block",
                }

        return {"safe": True, "reason": "", "action": "pass"}

class MemorySystem:
    """
    三层记忆系统：
    - 工作记忆：当前对话上下文（滑动窗口 + 摘要）
    - 短期记忆：近期对话摘要
    - 长期记忆：用户画像与偏好
    """

    def __init__(self, max_working_tokens: int = 4000):
        self.working_memory: list[dict] = []  # 当前对话
        self.short_term: list[dict] = []       # 近期摘要
        self.long_term: dict = {               # 用户画像
            "preferences": {},
            "history_summary": "",
            "interaction_count": 0,
        }
        self.max_working_tokens = max_working_tokens

    def add_message(self, role: str, content: str):
        """添加消息到工作记忆"""
        self.working_memory.append({
            "role": role,
            "content": content,
            "timestamp": datetime.now().isoformat(),
        })
        self.long_term["interaction_count"] += 1

    def get_context_messages(self) -> list[dict]:
        """
        获取当前上下文消息（滑动窗口策略）。
        如果工作记忆过长，保留最近 N 轮 + 历史摘要。
        """
        # 简化实现：保留最近 10 条消息
        recent = self.working_memory[-10:]

        messages = []
        # 加入历史摘要作为系统上下文
        if self.short_term:
            summary = "；".join([s["summary"] for s in self.short_term[-3:]])
            messages.append({
                "role": "system",
                "content": f"历史对话摘要：{summary}",
            })

        # 加入用户画像
        if self.long_term["preferences"]:
            prefs = json.dumps(self.long_term["preferences"], ensure_ascii=False)
            messages.append({
                "role": "system",
                "content": f"用户偏好：{prefs}",
            })

        messages.extend(recent)
        return messages

    def summarize_and_archive(self):
        """将当前工作记忆压缩为摘要，存入短期记忆"""
        if len(self.working_memory) < 4:
            return

        # 简化实现：取最后几条消息生成摘要
        recent_text = "\n".join(
            f"{m['role']}: {m['content'][:100]}"
            for m in self.working_memory[-6:]
        )
        summary = f"对话轮次 {len(self.short_term)+1}: {recent_text[:300]}"

        self.short_term.append({
            "summary": summary,
            "timestamp": datetime.now().isoformat(),
            "message_count": len(self.working_memory),
        })

        # 清空工作记忆（保留最近 2 条）
        self.working_memory = self.working_memory[-2:]

    def update_preference(self, key: str, value: str):
        """更新用户偏好"""
        self.long_term["preferences"][key] = value

    def get_stats(self) -> dict:
        """返回记忆系统统计"""
        return {
            "working_messages": len(self.working_memory),
            "short_term_summaries": len(self.short_term),
            "total_interactions": self.long_term["interaction_count"],
            "preferences": self.long_term["preferences"],
        }

class SmartAssistant:
    """
    生产级智能助手。

    核心流程：用户输入 → 安全检查 → 状态机管理 → LLM 推理 → 工具调用 → 输出审核 → 响应
    """

    def __init__(self, system_prompt: str = ""):
        # 组件初始化
        self.state = AssistantState.IDLE
        self.tool_registry = MCPToolRegistry()
        self.security = SecurityGuard()
        self.memory = MemorySystem()
        self.trace_counter = 0

        # LLM 客户端
        self.client = None
        if HAS_OPENAI and os.environ.get("OPENAI_API_KEY"):
            self.client = OpenAI()

        # 系统提示词
        self.system_prompt = system_prompt or (
            "你是一个专业的智能助手。你的核心原则：\n"
            "1. 理解用户意图，必要时追问澄清\n"
            "2. 高风险操作（删除、支付、发送）必须先确认\n"
            "3. 工具调用失败时，友好地告知用户并建议替代方案\n"
            "4. 不确定时坦诚说\"我不确定\"，不要编造信息\n"
            "5. 保持简洁、专业、友好的语气"
        )

    def _next_trace_id(self) -> str:
        self.trace_counter += 1
        return f"T{self.trace_counter:04d}"

    def register_tool(self, tool: MCPTool):
        """注册工具到助手"""
        self.tool_registry.register(tool)

    def _check_risk_level(self, tool_name: str) -> str:
        """检查工具的风险等级"""
        tool = self.tool_registry.get(tool_name)
        if not tool:
            return "unknown"
        return tool.risk_level

    def _simulate_llm(self, user_input: str) -> dict:
        """
        演示模式：无 API Key 时的规则引擎。
        真实项目中替换为 LLM 调用。
        """
        text = user_input.lower()

        # 意图识别 + 工具路由
        if any(kw in text for kw in ["天气", "气温", "下雨"]):
            # 提取城市
            city = "北京"
            for c in ["上海", "广州", "深圳", "杭州", "成都"]:
                if c in user_input:
                    city = c
                    break
            return {"action": "call_tool", "tool": "get_weather", "args": {"city": city}}

        if any(kw in text for kw in ["翻译", "translate"]):
            # 提取要翻译的文本（简化）
            text_to_translate = user_input.replace("翻译", "").replace("：", "").replace(":", "").strip()
            if not text_to_translate:
                text_to_translate = "Hello, how are you?"
            return {
                "action": "call_tool",
                "tool": "translate_text",
                "args": {"text": text_to_translate, "target_lang": "zh"},
            }

        if any(kw in text for kw in ["日程", "会议", "安排", "明天"]):
            return {
                "action": "call_tool",
                "tool": "create_calendar_event",
                "args": {"title": "待确认的日程", "date": "tomorrow"},
            }

        if any(kw in text for kw in ["记", "记住", "偏好"]):
            return {
                "action": "update_memory",
                "key": "last_request",
                "value": user_input,
            }

        # 默认回复
        return {"action": "reply", "content": self._default_reply(user_input)}

    def _default_reply(self, user_input: str) -> str:
        return (
            f"收到您的问题：「{user_input}」\n\n"
            "我是您的智能助手，可以帮您：\n"
            "  🌤️ 查询天气：「上海今天天气怎么样」\n"
            "  🌐 翻译文本：「翻译：Hello World」\n"
            "  📅 创建日程：「帮我安排明天的会议」\n"
            "  🧠 记住偏好：「记住我喜欢喝美式咖啡」\n\n"
            "请问需要什么帮助？"
        )

    def chat(self, user_input: str) -> str:
        """
        主对话入口。完整流程：
        1. 输入安全检查
        2. 状态转移
        3. 意图识别与工具路由
        4. 高风险确认
        5. 工具执行
        6. 输出审核
        7. 响应返回
        """
        trace_id = self._next_trace_id()
        console.print(f"\n[dim]━━━ Trace {trace_id} ━━━[/dim]")

        # ---- Step 1: 输入安全检查 ----
        safety_result = self.security.check_input(user_input)
        if not safety_result["safe"]:
            console.print(f"  [red]🛡️ 输入被拦截: {safety_result['reason']}[/red]")
            self.memory.add_message("user", user_input)
            self.memory.add_message("assistant", "[安全拦截]")
            return "⚠️ 检测到不安全的输入，请重新描述您的需求。"

        # ---- Step 2: 记录用户输入 ----
        self.memory.add_message("user", user_input)

        # ---- Step 3: 意图识别与路由 ----
        self.state = AssistantState.INTENT_RECOGNITION

        if self.client:
            # 真实模式：调用 LLM
            response = self.client.chat.completions.create(
                model="gpt-4o-mini",
                messages=[
                    {"role": "system", "content": self.system_prompt},
                    *self.memory.get_context_messages(),
                ],
                tools=self.tool_registry.list_tools() or None,
                tool_choice="auto",
            )
            msg = response.choices[0].message

            if msg.tool_calls:
                tool_call = msg.tool_calls[0]
                tool_name = tool_call.function.name
                tool_args = json.loads(tool_call.function.arguments)

                # ---- Step 4: 高风险确认 ----
                tool = self.tool_registry.get(tool_name)
                if tool and tool.risk_level == "high":
                    self.state = AssistantState.CONFIRMATION
                    confirm_msg = (
                        f"⚠️ 即将执行高风险操作：**{tool_name}**\n"
                        f"参数：{json.dumps(tool_args, ensure_ascii=False)}\n"
                        f"请回复「确认」继续，或「取消」中止。"
                    )
                    self.memory.add_message("assistant", confirm_msg)
                    return confirm_msg

                # ---- Step 5: 工具执行 ----
                self.state = AssistantState.TOOL_EXECUTING
                result = self.tool_registry.call(tool_name, tool_args, trace_id)

                if result["success"]:
                    tool_response = f"工具 {tool_name} 返回: {result['data']}"
                else:
                    tool_response = f"工具 {tool_name} 失败: {result['error']}"

                # 将工具结果传回 LLM 生成自然语言
                self.memory.add_message("system", tool_response)
                final_response = self.client.chat.completions.create(
                    model="gpt-4o-mini",
                    messages=[
                        {"role": "system", "content": self.system_prompt},
                        *self.memory.get_context_messages(),
                    ],
                )
                reply = final_response.choices[0].message.content
            else:
                reply = msg.content
        else:
            # 演示模式
            plan = self._simulate_llm(user_input)

            if plan["action"] == "call_tool":
                tool_name = plan["tool"]
                tool_args = plan["args"]

                # 高风险确认
                tool = self.tool_registry.get(tool_name)
                if tool and tool.risk_level == "high":
                    self.state = AssistantState.CONFIRMATION
                    return f"⚠️ 即将执行高风险操作：{tool_name}，参数：{tool_args}"

                # 执行工具
                self.state = AssistantState.TOOL_EXECUTING
                result = self.tool_registry.call(tool_name, tool_args, trace_id)

                if result["success"]:
                    reply = f"✅ {result['data']}"
                else:
                    reply = f"❌ 抱歉，执行失败：{result['error']}。请稍后重试或换个方式提问。"

            elif plan["action"] == "update_memory":
                self.memory.update_preference(plan["key"], plan["value"])
                reply = f"✅ 已记住：{plan['key']} = {plan['value']}"

            else:
                reply = plan.get("content", "我不太确定怎么帮您，能再说详细一点吗？")

        # ---- Step 6: 输出审核 ----
        output_check = self.security.check_output(reply)
        if not output_check["safe"]:
            console.print(f"  [red]🛡️ 输出被修改: {output_check['reason']}[/red]")
            reply = "⚠️ 回答中包含不适合展示的内容，已自动过滤。请换个方式提问。"

        # ---- Step 7: 记录并返回 ----
        self.state = AssistantState.RESULT_FEEDBACK
        self.memory.add_message("assistant", reply)

        # 定期压缩记忆
        if len(self.memory.working_memory) > 15:
            self.memory.summarize_and_archive()

        self.state = AssistantState.IDLE
        return reply

  2. MCP 工具注册：MCPTool 用标准 JSON Schema 描述输入输出，MCPToolRegistry 支持动态注册和 OpenAI Function Calling 格式输出。在真实项目中，MCP Server 通过 stdio 或 SSE 传输层提供工具。

  3. 分层安全：SecurityGuard 的 check_input 拦截提示词注入，check_output 防止敏感信息泄露。生产中应接入更强大的检测模型（如 Llama Guard）。

  4. 记忆系统：MemorySystem 实现三层记忆——工作记忆（当前对话）、短期记忆（摘要归档）、长期记忆（用户画像）。summarize_and_archive() 在对话过长时自动压缩。

  5. 可观测性：每次对话有 trace_id，工具调用记录耗时和结果，方便排查问题和评估效果。

✅ 最佳实践

结合 2025-2026 年行业实践，构建生产级智能助手建议遵循以下原则：

  1. 状态机而非自由态

  2. 不要让 LLM 完全自主决定对话流程。用状态机定义合法的状态转移，LLM 只负责在当前状态内做决策（如提取参数、生成回复）。这是 Klarna、Intercom 等头部 AI 客服产品的共同做法。

  3. 工具接入用标准协议

  4. 优先使用 MCP 或 OpenAI Agents SDK 接入工具，而非自研 JSON-RPC。MCP 的生态（5000+ 社区 Server）意味着你的助手可以零成本接入大量已有工具。如果需要接入企业内部系统，封装一个 MCP Server 即可。

  5. 安全是四层，不是一层

  6. 只做"二次确认"远远不够。输入过滤（防注入）、意图审核（权限校验）、输出审核（防泄露）、审计日志（可追溯）四层缺一不可。参考 Day 28 的安全框架。

  7. 记忆要分层，别一股脑塞上下文

  8. 工作记忆用滑动窗口，短期记忆用摘要压缩，长期记忆用结构化存储。当对话超过 10 轮时，必须压缩历史，否则 Token 成本和推理延迟都会失控。

  9. 用"任务完成率"而非"对话轮数"衡量效果

  10. 核心指标：首次解决率（FCR）、任务完成率（TCR）、人工转接率（ESI）、平均处理时长（AHT）。OpenAI 报告显示，Agent Mode 的任务完成率从 2025 年初的 45% 提升到 2026 年初的 72%，主要得益于工具生态的完善。

  11. 渐进式自动化

  12. 先让 AI 推荐话术（人工审核后发送），再自动填写（人工确认后提交），最后自动执行（仅高风险动作要确认）。Klarna 的 AI 客服就是从"辅助回复"逐步进化到"自主处理 2/3 对话"。

  13. 设计"优雅降级"策略

  14. 工具调用超时？给用户友好提示 + 建议替代方案。LLM 不确定？坦诚说"我不确定"并转人工。模型服务宕机？降级到规则引擎处理高频简单问题。永远不要让用户看到"系统错误"。

🤔 思考题

  1. 状态机的粒度：在你的业务场景中，智能助手的对话可以抽象为哪几个状态？哪些状态之间的转移需要人工确认？试着画出你自己的状态转移图。

  2. MCP vs 自研工具框架：MCP 作为开放协议有生态优势，但也有学习成本和协议限制。如果你要为一个中型企业设计内部智能助手，你会选择 MCP 还是自研工具接入框架？各自的 tradeoff 是什么？

  3. 记忆的隐私边界：长期记忆能显著提升用户体验（"和上次一样的偏好"），但也涉及隐私风险。如果用户要求"删除你对我的所有记忆"，你的系统能做到吗？如何验证记忆确实被清除？
