🎓 AI Native 实战课程 - Day 34: 上下文即状态 — 上下文窗口如何取代传统状态管理

📖 今日导读

前三章我们完成了 AI Native 的"三位一体"——数据即燃料（Day 1-11）、模型即引擎（Day 12-22）、Prompt 即接口（Day 23-33）。今天进入第四章：上下文即状态。

在 AI Native 产品中，上下文窗口（Context Window）不再只是"传给模型的输入"——它就是应用的状态容器。你不需要 Redis、不需要 Session Store、不需要状态机——你把什么塞进上下文窗口，应用就是什么状态。

这个命题解决的核心问题是：传统软件靠数据库和内存管理状态，AI Native 软件靠上下文窗口管理状态。理解这一点，你才能设计出真正连贯、个性化、有记忆的 AI 产品。

🔍 核心概念

1. 什么是"上下文即状态"？

传统 Web 应用的状态管理是这样的：

用户操作 → 后端处理 → 写入数据库/缓存 → 下次请求时读取
状态存在：数据库行、Session 对象、Redis Key、内存变量

AI Native 应用的状态管理变成了：

用户输入 + 历史对话 + 外部知识 → 塞入上下文窗口 → LLM 推理
状态存在：上下文窗口中的 Token 序列

核心洞察：上下文窗口 不是"输入管道"，它是 AI 应用的工作内存（Working Memory）。就像人类的短期记忆决定了此刻你能"想到"什么，上下文窗口决定了 LLM 此刻能"知道"什么。

这意味着：你管理上下文的方式，就是你管理应用状态的方式。

2. 上下文的三层结构

一个成熟的 AI Native 产品的上下文，由三层构成：

┌─────────────────────────────────────────┐
│  Layer 1: System Context（系统上下文）    │
│  角色定义 + 行为规则 + 安全约束           │
│  生命周期：应用级，几乎不变               │
├─────────────────────────────────────────┤
│  Layer 2: Session Context（会话上下文）   │
│  对话历史 + 用户偏好 + 当前任务状态       │
│  生命周期：会话级，随交互累积             │
├─────────────────────────────────────────┤
│  Layer 3: Retrieval Context（检索上下文） │
│  RAG 检索结果 + 工具返回 + 外部数据       │
│  生命周期：请求级，每次动态组装           │
└─────────────────────────────────────────┘

Layer 1 — System Context：相当于应用的"固件"。写一次，很少改。占据上下文窗口的 5-15%。这是 Prompt 工程的核心领域。

Layer 2 — Session Context：相当于应用的"运行时状态"。随用户交互不断累积——对话历史、用户表达的偏好、当前任务的进展。这是最容易溢出上下文窗口的部分，也是最需要精心管理的部分。

Layer 3 — Retrieval Context：相当于应用的"外部存储"。每次请求时动态检索、动态注入。RAG（检索增强生成）的本质就是"把数据库中的状态临时加载到上下文窗口"——和操作系统把磁盘数据加载到内存是一个道理。

3. 上下文窗口 = 工作内存：一个操作系统类比

理解上下文管理最好的类比，是操作系统的虚拟内存管理：

操作系统概念 AI Native 对应
CPU 寄存器 当前轮次的用户输入
L1/L2 缓存 System Prompt（最快访问，最常使用）
内存 (RAM) 上下文窗口（有限容量，高速访问）
磁盘/SSD 向量数据库 / 知识库（大容量，需要"加载"）
页面置换算法 上下文压缩 / 摘要 / 滑动窗口
虚拟内存 RAG — 把磁盘数据"映射"到内存

这个类比揭示了一个关键设计原则：上下文管理的本质是"换页策略"——当上下文窗口装不下所有状态时，你需要决定保留什么、压缩什么、丢弃什么。

2025-2026 年的主流策略：

  • 滑动窗口（Sliding Window）：只保留最近 N 轮对话，丢弃更早的。简单粗暴，但会丢失重要上下文。
  • 摘要压缩（Summary Buffer）：把旧对话压缩成摘要，保留关键信息。LangChain 的 ConversationSummaryBufferMemory 就是这个思路。
  • 分层缓存（Tiered Cache）：像操作系统一样分层——热数据在上下文窗口，温数据在向量数据库，冷数据在持久化存储。
  • 智能检索（Smart Retrieval）：每次请求时，根据当前问题动态检索相关上下文注入窗口。这是 RAG 的核心价值。

4. 2025-2026 年的三大趋势

趋势一：上下文窗口爆炸式增长

2024 年 GPT-4 的上下文窗口是 128K tokens，Claude 3 是 200K。到 2025-2026 年，Gemini 1.5 Pro 达到 2M tokens，Claude 3.5 达到 200K，许多模型支持 1M+ tokens。但这不意味着"不需要上下文管理了"——恰恰相反，窗口越大，"塞什么进去"的决策越重要。就像内存从 4GB 升到 64GB，你仍然需要好的内存管理。

趋势二：上下文工程（Context Engineering）成为独立学科

2025 年，上下文工程（Context Engineering）从"Prompt Engineering 的子集"升级为独立工程领域。它关注的核心问题不再是"怎么写好 Prompt"，而是"怎么管理好上下文的生命周期"——检索什么、压缩什么、缓存什么、何时刷新。

趋势三：Agent 的上下文管理是最大挑战

AI Agent 需要在长任务中维持上下文一致性。一个 Agent 可能执行 50+ 步操作，跨越 10+ 个工具调用——如何在这么长的任务链中保持"记忆"不断裂？这是 2025-2026 年 Agent 框架（LangGraph、CrewAI、AutoGen）的核心技术难题。

- 三层结构：System Context / Session Context / Retrieval Context

# ============================================================
# 1. Token 计数器 — 上下文管理的基础
# ============================================================

class TokenCounter:
    """Token 计数器 — 精确计算上下文占用"""

    def __init__(self, model: str = "gpt-4o"):
        self.model = model
        if HAS_TIKTOKEN:
            try:
                self.encoding = tiktoken.encoding_for_model(model)
            except KeyError:
                self.encoding = tiktoken.get_encoding("cl100k_base")
        else:
            self.encoding = None

    def count(self, text: str) -> int:
        """计算文本的 token 数"""
        if self.encoding:
            return len(self.encoding.encode(text))
        # 粗略估算：中文 1 字 ≈ 2 tokens，英文 1 词 ≈ 1.3 tokens
        return len(text) // 2


# ============================================================
# 2. 上下文片段 — 最小管理单元
# ============================================================

@dataclass
class ContextChunk:
    """上下文片段 — 上下文窗口中的最小管理单元"""
    content: str                    # 内容
    layer: str                      # 所属层：system / session / retrieval
    priority: float                 # 优先级 0-1（1 = 最高）
    token_count: int = 0            # token 数量
    created_at: str = ""            # 创建时间
    source: str = ""                # 来源标识
    metadata: dict = field(default_factory=dict)  # 元数据

    def __post_init__(self):
        if not self.created_at:
            self.created_at = datetime.now().isoformat()
        counter = TokenCounter()
        if self.token_count == 0:
            self.token_count = counter.count(self.content)


# ============================================================
# 3. 上下文管理引擎
# ============================================================

class ContextEngine:
    """
    上下文管理引擎 — AI Native 应用的状态管理器

    职责：
    - 管理上下文三层结构
    - 智能压缩和淘汰
    - 动态检索和注入
    - Token 预算控制
    """

    def __init__(self, max_tokens: int = 128000, model: str = "gpt-4o"):
        self.max_tokens = max_tokens
        self.model = model
        self.counter = TokenCounter(model)

        # 三层上下文存储
        self.system_chunks: list[ContextChunk] = []      # Layer 1
        self.session_chunks: deque[ContextChunk] = deque(maxlen=100)  # Layer 2
        self.retrieval_chunks: list[ContextChunk] = []   # Layer 3

        # 预算分配（百分比）
        self.budget = {
            "system": 0.15,     # 15% 给系统上下文
            "session": 0.50,    # 50% 给会话上下文
            "retrieval": 0.25,  # 25% 给检索上下文
            "reserve": 0.10,    # 10% 留给生成
        }

        # 压缩历史
        self.compression_log: list[dict] = []

    @property
    def total_tokens(self) -> int:
        """当前上下文总 token 数"""
        return sum(c.token_count for c in self._all_chunks())

    @property
    def available_tokens(self) -> int:
        """剩余可用 token 数"""
        return self.max_tokens - self.total_tokens

    def _all_chunks(self) -> list[ContextChunk]:
        return self.system_chunks + list(self.session_chunks) + self.retrieval_chunks

    def _budget_tokens(self, layer: str) -> int:
        """某层的 token 预算"""
        return int(self.max_tokens * self.budget[layer])

    # ---- Layer 1: System Context ----

    def set_system_context(self, content: str, source: str = "system"):
        """设置系统上下文（覆盖）"""
        chunk = ContextChunk(
            content=content,
            layer="system",
            priority=1.0,
            source=source,
        )
        self.system_chunks = [chunk]
        if HAS_RICH:
            console.print(f"  [green]✓[/green] 系统上下文已设置 ({chunk.token_count} tokens)")

    # ---- Layer 2: Session Context ----

    def add_session_context(self, role: str, content: str, priority: float = 0.5):
        """添加会话上下文（对话轮次）"""
        formatted = f"[{role}]: {content}"
        chunk = ContextChunk(
            content=formatted,
            layer="session",
            priority=priority,
            source=f"turn_{len(self.session_chunks)}",
            metadata={"role": role},
        )
        self.session_chunks.append(chunk)

        # 检查是否需要压缩
        session_tokens = sum(c.token_count for c in self.session_chunks)
        if session_tokens > self._budget_tokens("session"):
            self._compress_session()

    def _compress_session(self):
        """压缩会话上下文 — 摘要旧对话"""
        budget = self._budget_tokens("session")
        current_tokens = sum(c.token_count for c in self.session_chunks)

        if current_tokens <= budget:
            return

        # 策略：把前 50% 的对话压缩成摘要
        chunks = list(self.session_chunks)
        split_point = len(chunks) // 2
        old_chunks = chunks[:split_point]
        new_chunks = chunks[split_point:]

        # 生成摘要（在演示模式下模拟）
        old_text = "\n".join(c.content for c in old_chunks)
        summary_text = self._generate_summary(old_text)

        summary_chunk = ContextChunk(
            content=f"[对话摘要]: {summary_text}",
            layer="session",
            priority=0.7,
            source="compression",
            metadata={"type": "summary", "compressed_count": len(old_chunks)},
        )

        # 替换
        self.session_chunks.clear()
        self.session_chunks.append(summary_chunk)
        for c in new_chunks:
            self.session_chunks.append(c)

        self.compression_log.append({
            "timestamp": datetime.now().isoformat(),
            "compressed_chunks": len(old_chunks),
            "tokens_saved": sum(c.token_count for c in old_chunks) - summary_chunk.token_count,
        })

        if HAS_RICH:
            saved = sum(c.token_count for c in old_chunks) - summary_chunk.token_count
            console.print(f"  [yellow]📦[/yellow] 上下文压缩：{len(old_chunks)} 轮 → 摘要 ({saved} tokens 已释放)")

    def _generate_summary(self, text: str) -> str:
        """生成对话摘要"""
        if HAS_OPENAI and os.getenv("OPENAI_API_KEY"):
            try:
                client = OpenAI()
                response = client.chat.completions.create(
                    model="gpt-4o-mini",
                    messages=[{
                        "role": "system",
                        "content": "请将以下对话压缩为 2-3 句话的摘要，保留关键信息（用户需求、做出的决定、重要结论）。"
                    }, {
                        "role": "user",
                        "content": text
                    }],
                    max_tokens=200,
                    temperature=0.1,
                )
                return response.choices[0].message.content
            except Exception:
                pass

        # 演示模式：模拟摘要
        lines = text.split("\n")
        key_points = [l for l in lines if any(kw in l for kw in ["需要", "决定", "选择", "方案", "问题"])]
        if key_points:
            return "用户讨论了：" + "；".join(key_points[:3])
        return f"（已压缩 {len(lines)} 轮对话的摘要）"

    # ---- Layer 3: Retrieval Context ----

    def inject_retrieval(self, content: str, source: str, relevance: float = 0.8):
        """注入检索上下文"""
        chunk = ContextChunk(
            content=content,
            layer="retrieval",
            priority=relevance,
            source=source,
            metadata={"type": "retrieval"},
        )

        # 检查预算，淘汰低优先级的
        retrieval_tokens = sum(c.token_count for c in self.retrieval_chunks)
        while retrieval_tokens + chunk.token_count > self._budget_tokens("retrieval") and self.retrieval_chunks:
            # 淘汰优先级最低的
            self.retrieval_chunks.sort(key=lambda c: c.priority)
            removed = self.retrieval_chunks.pop(0)
            retrieval_tokens -= removed.token_count
            if HAS_RICH:
                console.print(f"  [dim]♻️ 淘汰低优先级检索: {removed.source}[/dim]")

        self.retrieval_chunks.append(chunk)

    # ---- 构建最终上下文 ----

    def build_messages(self, user_input: str) -> list[dict]:
        """构建最终的消息列表"""
        messages = []

        # Layer 1: System
        for chunk in self.system_chunks:
            messages.append({"role": "system", "content": chunk.content})

        # Layer 2: Session
        for chunk in self.session_chunks:
            role = chunk.metadata.get("role", "user")
            # 摘要和压缩内容作为 system 注入
            if "[对话摘要]" in chunk.content or "[compressed]" in chunk.content:
                messages.append({"role": "system", "content": chunk.content})
            else:
                messages.append({"role": role, "content": chunk.content})

        # Layer 3: Retrieval
        if self.retrieval_chunks:
            retrieval_text = "\n---\n".join(
                f"[来源: {c.source}] {c.content}" for c in self.retrieval_chunks
            )
            messages.append({
                "role": "system",
                "content": f"以下是与当前问题相关的参考资料：\n\n{retrieval_text}"
            })

        # 当前用户输入
        messages.append({"role": "user", "content": user_input})

        return messages

    # ---- 诊断和可视化 ----

    def status(self) -> dict:
        """上下文状态报告"""
        system_tokens = sum(c.token_count for c in self.system_chunks)
        session_tokens = sum(c.token_count for c in self.session_chunks)
        retrieval_tokens = sum(c.token_count for c in self.retrieval_chunks)
        total = system_tokens + session_tokens + retrieval_tokens

        return {
            "max_tokens": self.max_tokens,
            "total_used": total,
            "usage_pct": round(total / self.max_tokens * 100, 1),
            "available": self.max_tokens - total,
            "layers": {
                "system": {"tokens": system_tokens, "chunks": len(self.system_chunks)},
                "session": {"tokens": session_tokens, "chunks": len(self.session_chunks)},
                "retrieval": {"tokens": retrieval_tokens, "chunks": len(self.retrieval_chunks)},
            },
            "compressions": len(self.compression_log),
        }

    def visualize(self):
        """可视化上下文使用情况"""
        if not HAS_RICH:
            print(json.dumps(self.status(), indent=2, ensure_ascii=False))
            return

        status = self.status()

        # 状态表
        table = Table(title="📊 上下文状态", show_header=True)
        table.add_column("层", style="bold")
        table.add_column("Token 数", justify="right")
        table.add_column("片段数", justify="right")
        table.add_column("预算占比", justify="right")
        table.add_column("状态")

        for layer_name, layer_data in status["layers"].items():
            budget_pct = self.budget[layer_name] * 100
            actual_pct = layer_data["tokens"] / self.max_tokens * 100 if self.max_tokens > 0 else 0
            emoji = "🟢" if actual_pct <= budget_pct else "🔴"
            table.add_row(
                layer_name.capitalize(),
                f"{layer_data['tokens']:,}",
                str(layer_data["chunks"]),
                f"{actual_pct:.1f}% / {budget_pct:.0f}%",
                emoji,
            )

        table.add_row(
            "[bold]总计[/bold]",
            f"[bold]{status['total_used']:,}[/bold]",
            str(sum(l["chunks"] for l in status["layers"].values())),
            f"[bold]{status['usage_pct']}%[/bold]",
            "✅" if status["usage_pct"] < 90 else "⚠️",
        )

        console.print(table)

        # Token 使用条
        bar_len = 50
        used_len = int(status["usage_pct"] / 100 * bar_len)
        bar = "█" * used_len + "░" * (bar_len - used_len)
        console.print(f"\n  Token 使用: [{bar}] {status['usage_pct']}%")
        console.print(f"  已用: {status['total_used']:,} / {status['max_tokens']:,}")
        console.print(f"  压缩次数: {status['compressions']}")

✅ 最佳实践

结合 2025-2026 年的行业实践，四条上下文管理的实战建议：

1. 分层管理，而不是平铺直叙

不要把所有信息一股脑塞进一个巨大的 System Prompt。分三层管理——系统指令、会话历史、动态检索——每层有独立的生命周期和 token 预算。这样你才能精确控制"什么是永远在的"、"什么会随时间淘汰"、"什么按需加载"。

2. 压缩不是丢弃，是提炼

当上下文窗口不够用时，不要简单地滑动窗口丢掉旧对话。摘要压缩保留了信息的关键语义，代价是增加一次 LLM 调用。但这个代价远小于"AI 变成了金鱼"带来的用户体验损失。LangChain 的 ConversationSummaryBufferMemory 和 LlamaIndex 的 ChatSummaryMemoryBuffer 是开箱即用的方案。

3. 检索上下文要"小而精"，不要"大而全"

RAG 的常见错误是检索太多内容塞进上下文——10 个文档片段可能只有 3 个是真正相关的。冗余上下文不仅浪费 token，还会干扰模型判断（"Lost in the Middle"效应：模型倾向于忽略中间位置的信息）。实践建议：检索 top-3 而不是 top-10，并用重排序（Reranker）进一步筛选。

4. 为 Agent 设计"检查点"机制

长任务 Agent 的最大风险是上下文断裂——执行到第 30 步时，已经忘了第 5 步做了什么。解决方案是检查点（Checkpoint）机制：每完成一个关键步骤，把当前状态摘要保存到外部存储；当需要回顾时，从检查点恢复而不是从头开始。LangGraph 的 State 就是这个思路的实现。

🤔 思考题

  1. 上下文窗口 200K 了，还需要 RAG 吗？ Claude 3.5 支持 200K tokens，Gemini 支持 2M tokens——直接把所有文档塞进去不就行了？为什么 RAG 仍然重要？提示：从成本、延迟、精度三个维度思考。

  2. "上下文即状态"的边界在哪？ 一个 AI 产品如果完全依赖上下文窗口管理状态，会遇到什么问题？哪些状态仍然需要传统数据库？提示：想想"用户关掉浏览器再回来"的场景。

  3. AI 的"遗忘"是 Bug 还是 Feature？ 人类会遗忘，这被认为是大脑的"特征压缩"。AI 应用的上下文压缩，是否也应该引入"主动遗忘"机制——不是所有信息都值得记住？如何定义"值得记住"的标准？
