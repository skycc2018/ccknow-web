AI Native 实战课程 - Day 50: 第五章 - 生成即服务

📖 今日导读

前四章我们建立了 AI Native 产品的核心认知框架——从本质区分、行业拐点、Prompt 即接口到上下文即状态。但所有这些能力都需要一个根本前提：你能以合理的成本、足够的速度、可靠的稳定性调用到 AI 模型。这就是第五章要讨论的"生成即服务"（Generation as a Service, GaaS）。

2023 年，调用一次 GPT-4 要花几美分，延迟动辄数秒，可用性也时好时坏。到了 2026 年，格局已经彻底改变：推理成本下降了 100 倍以上，延迟降至毫秒级，开源模型性能追平甚至超越闭源模型，专用芯片挑战 GPU 垄断。AI 推理已经从"稀缺资源"变成了"水电煤"——一种按需获取、按量计费的基础服务。 理解这个生态，是构建 AI Native 产品的必修课。今天我们系统拆解生成即服务的技术栈、商业格局和最佳实践。

🔍 核心概念

1. 什么是"生成即服务"？

生成即服务（Generation as a Service）是指通过 API 按需调用 AI 模型的生成能力，而无需自行部署和管理模型基础设施。它是 AI Native 产品的"发动机"——你不需要造发动机，但必须知道怎么选、怎么用。

GaaS 的核心价值链：

模型提供方 → 推理优化层 → API 网关 → 应用层
（训练/微调）  （加速/量化）  （路由/计费）  （你的产品）

为什么叫"生成"而不叫"推理"？ 因为它的核心价值不只是"运行模型"，而是生成有价值的内容——文本、代码、图像、音频、视频。"推理"是技术视角，"生成"是产品视角。

2. GaaS 市场的三层金字塔

第一层：闭源模型 API（"品牌发电厂"）

OpenAI、Anthropic、Google 三大巨头提供自研模型的 API 服务。它们是"发电厂"——你用的电（模型能力）是它们发的，你按度（token）付费。

  • OpenAI：GPT-4o（$2.5/$10 per 1M tokens）、o3 推理模型、Responses API
  • Anthropic：Claude 3.5 Sonnet（$3/$15）、200K 上下文、工具调用
  • Google：Gemini 2.0 Flash（$0.075/$0.30）、多模态原生

特点：模型能力最强、价格最高、不可自部署、存在供应商锁定风险。

第二层：开源模型推理平台（"电力公司"）

Together AI、Fireworks AI、Groq 等公司托管开源模型（Llama、DeepSeek、Mistral），提供优化后的推理服务。它们是"电力公司"——电（模型）是开源的，但它们提供了更好的传输和配送。

  • Together AI：$305M+ 融资，开源模型全栈托管
  • Fireworks AI：$252M+ 融资，FireAttention 引擎，号称 5-10x 加速
  • Groq：自研 LPU 芯片，sub-100ms TTFT，不依赖 GPU
  • Cerebras：晶圆级芯片 WSE-3，20x GPU 推理速度

特点：价格低、速度快、模型选择多，但需要自己处理模型选择和微调。

第三层：基础设施平台（"电网"）

提供 GPU 算力和部署工具，让你自己跑模型。

  • Modal：Serverless GPU，按秒计费，Python 原生
  • Replicate：一键部署开源模型，容器化托管
  • Lambda Labs：GPU 云 + 推理 API
  • 自建方案：vLLM + Kubernetes + 自有 GPU 集群

特点：灵活度最高，但需要工程能力。

3. 定价模型的演变

GaaS 市场经历了三代定价模型：

第一代：按 token 计费（2023-2024）

输入：$X / 1M tokens
输出：$Y / 1M tokens

简单直接，但对用户不友好——你很难预估一次调用花多少钱。

第二代：分层计费（2024-2025）

实时 API：标准价格
Batch API：50% 折扣（异步处理，24h 内返回）
缓存命中：90% 折扣（Anthropic Context Caching）

让开发者根据场景选择性价比最优的调用方式。

第三代：智能路由计费（2025-2026）

简单任务 → 自动路由到小模型（$0.1/1M tokens）
复杂任务 → 自动路由到大模型（$10/1M tokens）
重复查询 → 语义缓存命中（接近零成本）

LiteLLM、Portkey 等 API 网关实现了跨供应商的智能路由，根据任务复杂度自动选择最经济的模型。

价格趋势：每年下降 50-70%。 DeepSeek 的出现加速了这一进程——DeepSeek-V3 以 $0.27/$1.10 的定价（仅为 GPT-4 的 1/10）迫使全行业跟进降价。预计到 2026 年底，GPT-4 级别的能力将降至 <$1/1M tokens。

4. 推理优化的关键技术

为什么推理成本能下降这么快？背后是四大技术驱动力：

量化（Quantization）

将模型权重从 FP16 压缩到 INT4/FP8，内存占用减少 4-8 倍，推理速度提升 2-3 倍，质量损失极小。

FP32 → FP16 → FP8 → INT4（GGUF/GPTQ/AWQ）
精度 ↓↓↓↓    ↓↓↓    ↓↓    ↓
速度 ×1     ×2    ×4    ×6
内存 ÷1     ÷2    ÷4    ÷8

推测解码（Speculative Decoding）

用小模型"草拟"多个 token，大模型一次性验证。2-3x 加速，零质量损失。Fireworks、Together、Google 都已部署。

KV Cache 优化

  • PagedAttention（vLLM）：像操作系统管理内存页一样管理 KV Cache
  • RadixAttention（SGLang）：前缀共享，多轮对话复用缓存
  • FlashAttention-3：内存高效的注意力计算

定制芯片

Groq LPU、Cerebras WSE、SambaNova RDU 摆脱 GPU 依赖，提供确定性延迟。

2025 年初，中国 AI 公司 DeepSeek 发布了 DeepSeek-V3 和 DeepSeek-R1 两个开源模型，在性能上接近甚至超越 GPT-4，但定价仅为后者的 1/10（V3: $0.27/$1.10 per 1M tokens）。更关键的是，DeepSeek 采用了 MoE（Mixture of Experts）架构——671B 总参数但仅 37B 活跃参数，使得推理成本极低。

连锁反应： - Together AI、Fireworks AI 在一周内跟进降价 - OpenAI 推出 GPT-4o-mini（$0.15/$0.60）作为低价替代 - 整个行业的"AI 推理成本预期"被重置 - 开源模型成为推理平台的主力，托管收入超过闭源 API

启示：在 GaaS 市场，开源模型的竞争压力是推动价格下降的最大力量。构建 AI Native 产品时，不要绑死在一个供应商上——今天最便宜的供应商，明天可能被新玩家颠覆。

案例二：Groq 的芯片级创新

Groq 不做软件优化，而是从硬件层面重新设计了推理芯片——LPU（Language Processing Unit）。与 GPU 的通用计算不同，LPU 专门为 Transformer 推理设计，提供确定性延迟（每次推理的时间几乎相同）。

关键数据： - Llama 3.3 70B：$0.59/$0.79 per 1M tokens - TTFT（首 token 延迟）：<100ms，比 GPU 方案快 5-10 倍 - 吞吐量：单芯片可达数百 tokens/秒

产品影响：Groq 的超低延迟使得实时对话、实时代码补全、实时翻译等场景成为可能。Cursor 的代码补全之所以"丝滑"，背后就是推理延迟的极致优化。

启示：推理延迟 是 AI Native 产品的隐形竞争壁垒。用户感知到的不是"这个 AI 聪不聪明"，而是"它快不快"。100ms 以内的响应是"即时感"的门槛。

"""
Day 50: 生成即服务 - 智能 API 网关示例
功能：任务路由 + 语义缓存 + 成本追踪
"""

import hashlib
import json
import time
from dataclasses import dataclass, field
from enum import Enum
from typing import Optional


# ============ 1. 模型注册表 ============

class ModelTier(Enum):
    """模型层级：从便宜到贵"""
    MINI = "mini"       # 简单任务：分类、提取、格式转换
    STANDARD = "standard"  # 通用任务：摘要、翻译、问答
    PREMIUM = "premium"    # 复杂任务：推理、创作、代码生成


@dataclass
class ModelConfig:
    name: str
    provider: str
    tier: ModelTier
    input_price: float   # $ per 1M tokens
    output_price: float  # $ per 1M tokens
    max_tokens: int
    latency_ms: int      # 平均延迟


# 模型注册表（2026 年价格）
MODEL_REGISTRY = {
    "gpt-4o-mini": ModelConfig(
        name="gpt-4o-mini", provider="openai",
        tier=ModelTier.MINI, input_price=0.15, output_price=0.60,
        max_tokens=16384, latency_ms=300
    ),
    "deepseek-v3": ModelConfig(
        name="deepseek-v3", provider="deepseek",
        tier=ModelTier.STANDARD, input_price=0.27, output_price=1.10,
        max_tokens=65536, latency_ms=500
    ),
    "gpt-4o": ModelConfig(
        name="gpt-4o", provider="openai",
        tier=ModelTier.PREMIUM, input_price=2.50, output_price=10.00,
        max_tokens=16384, latency_ms=800
    ),
    "claude-sonnet": ModelConfig(
        name="claude-3.5-sonnet", provider="anthropic",
        tier=ModelTier.PREMIUM, input_price=3.00, output_price=15.00,
        max_tokens=8192, latency_ms=600
    ),
}


# ============ 2. 任务分类器（简化版） ============

# 用规则引擎做任务分类（V1 不用 AI，V2 可升级为小模型分类）
COMPLEXITY_KEYWORDS = {
    ModelTier.MINI: [
        "分类", "提取", "格式", "转换", "列表", "是或否",
        "classify", "extract", "format", "list", "yes or no"
    ],
    ModelTier.PREMIUM: [
        "分析", "推理", "为什么", "代码", "写一篇", "设计",
        "策略", "对比", "评估", "深度", "完整",
        "analyze", "reason", "why", "code", "write a", "design",
        "strategy", "compare", "evaluate", "deep", "complete"
    ],
}


def classify_task(prompt: str) -> ModelTier:
    """根据 prompt 内容判断任务复杂度"""
    prompt_lower = prompt.lower()

    # 检查是否匹配复杂任务关键词
    for keyword in COMPLEXITY_KEYWORDS[ModelTier.PREMIUM]:
        if keyword in prompt_lower:
            return ModelTier.PREMIUM

    # 检查是否匹配简单任务关键词
    for keyword in COMPLEXITY_KEYWORDS[ModelTier.MINI]:
        if keyword in prompt_lower:
            return ModelTier.MINI

    # 默认为标准任务
    return ModelTier.STANDARD


def select_model(tier: ModelTier, prefer_speed: bool = False) -> ModelConfig:
    """根据层级选择最优模型"""
    candidates = [m for m in MODEL_REGISTRY.values() if m.tier == tier]
    if not candidates:
        # 降级：找不到同级模型，用更便宜的
        candidates = list(MODEL_REGISTRY.values())

    if prefer_speed:
        return min(candidates, key=lambda m: m.latency_ms)
    else:
        return min(candidates, key=lambda m: m.input_price + m.output_price)


# ============ 3. 语义缓存 ============

class SemanticCache:
    """基于 prompt 哈希的缓存（简化版；生产环境用向量相似度）"""

    def __init__(self, ttl_seconds: int = 3600):
        self.cache: dict[str, dict] = {}
        self.ttl = ttl_seconds
        self.hits = 0
        self.misses = 0

    def _hash(self, prompt: str, model: str) -> str:
        """生成缓存键"""
        content = f"{model}:{prompt.strip().lower()}"
        return hashlib.md5(content.encode()).hexdigest()

    def get(self, prompt: str, model: str) -> Optional[str]:
        """查询缓存"""
        key = self._hash(prompt, model)
        if key in self.cache:
            entry = self.cache[key]
            if time.time() - entry["timestamp"] < self.ttl:
                self.hits += 1
                return entry["response"]
            else:
                del self.cache[key]  # 过期清理
        self.misses += 1
        return None

    def set(self, prompt: str, model: str, response: str):
        """写入缓存"""
        key = self._hash(prompt, model)
        self.cache[key] = {
            "response": response,
            "timestamp": time.time()
        }

    @property
    def hit_rate(self) -> float:
        total = self.hits + self.misses
        return self.hits / total if total > 0 else 0.0


# ============ 4. 成本追踪器 ============

@dataclass
class CostTracker:
    """追踪 API 调用成本"""
    total_input_tokens: int = 0
    total_output_tokens: int = 0
    total_cost_usd: float = 0.0
    total_calls: int = 0
    cache_savings: float = 0.0
    call_log: list = field(default_factory=list)

    def record(self, model: ModelConfig, input_tokens: int, output_tokens: int,
               cached: bool = False):
        self.total_calls += 1
        self.total_input_tokens += input_tokens
        self.total_output_tokens += output_tokens

        cost = (input_tokens * model.input_price / 1_000_000 +
                output_tokens * model.output_price / 1_000_000)

        if cached:
            self.cache_savings += cost
        else:
            self.total_cost_usd += cost

        self.call_log.append({
            "model": model.name,
            "input_tokens": input_tokens,
            "output_tokens": output_tokens,
            "cost_usd": round(cost, 6),
            "cached": cached,
            "timestamp": time.strftime("%Y-%m-%d %H:%M:%S")
        })

    def summary(self) -> dict:
        return {
            "total_calls": self.total_calls,
            "total_cost_usd": round(self.total_cost_usd, 4),
            "cache_savings_usd": round(self.cache_savings, 4),
            "avg_cost_per_call": round(
                self.total_cost_usd / max(self.total_calls, 1), 4
            ),
            "total_tokens": self.total_input_tokens + self.total_output_tokens,
        }


# ============ 5. 智能网关主类 ============

class SmartGateway:
    """智能 API 网关：自动路由 + 缓存 + 成本追踪"""

    def __init__(self):
        self.cache = SemanticCache(ttl_seconds=3600)
        self.cost_tracker = CostTracker()

    def route(self, prompt: str, prefer_speed: bool = False) -> dict:
        """
        智能路由：分析 prompt → 选择模型 → 检查缓存 → 返回结果
        """
        # 1. 任务分类
        tier = classify_task(prompt)
        model = select_model(tier, prefer_speed=prefer_speed)

        # 2. 检查缓存
        cached_response = self.cache.get(prompt, model.name)
        if cached_response:
            self.cost_tracker.record(model, 0, 0, cached=True)
            return {
                "response": cached_response,
                "model": model.name,
                "tier": tier.value,
                "cached": True,
                "cost_usd": 0.0,
                "note": "Cache hit! 完全免费"
            }

        # 3. 模拟 API 调用（生产环境替换为真实调用）
        simulated_input_tokens = len(prompt) // 4  # 粗略估算
        simulated_output_tokens = simulated_input_tokens * 3
        simulated_response = f"[{model.name} 的模拟响应] 对于 prompt: {prompt[:50]}..."

        # 4. 记录成本
        self.cost_tracker.record(model, simulated_input_tokens, simulated_output_tokens)

        # 5. 写入缓存
        self.cache.set(prompt, model.name, simulated_response)

        cost = (simulated_input_tokens * model.input_price / 1_000_000 +
                simulated_output_tokens * model.output_price / 1_000_000)

        return {
            "response": simulated_response,
            "model": model.name,
            "tier": tier.value,
            "cached": False,
            "cost_usd": round(cost, 6),
            "input_tokens": simulated_input_tokens,
            "output_tokens": simulated_output_tokens
        }

    def report(self) -> dict:
        """生成成本报告"""
        return {
            **self.cost_tracker.summary(),
            "cache_hit_rate": f"{self.cache.hit_rate:.1%}",
            "cache_size": len(self.cache.cache),
        }

✅ 最佳实践

1. 多供应商策略，避免锁定

永远不要只依赖一个 API 供应商。使用 LiteLLM 或 Portkey 等 API 网关实现： - 自动降级：主供应商挂了，自动切换备用 - 成本优化：同类任务在不同供应商间比价 - 地理路由：国内用户走 DeepSeek/通义，海外用户走 OpenAI

2. Right-size 模型选择

不是所有任务都需要最强模型。经验法则： - 分类/提取/格式转换：7B-14B 小模型足矣（$0.1/1M tokens） - 摘要/翻译/问答：70B 开源模型（DeepSeek-V3, Llama 3.3） - 推理/创作/代码：需要顶级模型（GPT-4o, Claude Sonnet） - 用小模型做 80% 的工作，大模型做 20% 的高价值工作

3. 善用 Batch API

对于非实时任务（批量翻译、数据标注、报告生成），使用 Batch API： - OpenAI Batch API：50% 折扣 - Fireworks Batch：类似折扣 - 容忍 24 小时延迟，换取一半成本

4. 语义缓存是成本杀手

对于重复或相似的查询，语义缓存可以将成本降至接近零： - 精确缓存：相同 prompt 直接命中（如上面的代码示例） - 语义缓存：用向量相似度匹配"意思相近"的查询（生产环境推荐） - 预计可节省 30-50% 的 API 成本

5. 监控推理延迟，而非只看成本

延迟对用户体验的影响远大于成本： - <200ms：用户感觉"即时"（对话、补全） - 200ms-1s：用户感觉"流畅"（问答、生成） - 1-5s：用户感觉"在等待"（需要进度指示） - >5s：用户感觉"卡住了"（需要异步处理）

选择模型时，把延迟作为和成本同等重要的决策因素。
